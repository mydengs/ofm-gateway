# OFM Gateway — 业务逻辑说明

本文回答运营方最关心的三个问题：**额度到底怎么算**、**什么时候会失败**、
**失败之后系统怎么自愈**。

## 一、上游额度模型

上游 = OpenCode Zen 免费网关（`opencode.ai/inference/v1/*`，免密凭据 `Bearer public`）
\+ Kilo 公共网关（独立免费池，互不影响）。没有账号体系，靠四重指纹识别：

| 维度 | 机制 | 运营含义 |
|---|---|---|
| **出口 IP** | 主计额桶。同一 IP 免费额度耗尽 → 429，窗口递增（实测最长 17.5h） | **换 IP = 重开额度**，本项目核心对策 |
| **会话 session** | 每个对话映射稳定 session id（`session-map.json`），额度按会话计 | 勿删 session-map；每请求新铸 session 必 429 |
| **项目 project** | `x-opencode-project` 头按 project×出口分桶 | 插件自动随机化，无需关心 |
| **客户端指纹** | UA + `x-opencode-*` 头 + 官方 13 工具集 + 官方系统提示词 + TLS 指纹（Bun） | 不符 → 403 FreeTierError 整车道锁死；本项目用 standalone 自带整形，合规 |

**没有公开的固定数字**（如"每 IP 每天 N 次"）。观测参考：重度 agent 使用
（每轮系统提示 ~5.8k tokens）约 2.5 小时 / 28 万输入 token 后撞墙。

## 二、三种失败与判别

| 特征 | 类型 | 处置 |
|---|---|---|
| 200~600ms 内秒失败，报 `FreeUsageLimitError` | **429 额度墙**（断路器开窗） | 看守换 IP + 重启清窗 |
| ~10 秒超时 / `Bun worker failed before completing the response` | **代理隧道坏**（坏网关） | 看守健康探测换 sid |
| 立即 403 `FreeTierError` | 客户端指纹被拒（整车道） | 检查是否上游规则变更（升级 standalone） |

⚠️ **易误判点**：直连上游手工测试时，**非流式请求一律 429**——看着像额度
耗尽，实际是形态被拒（上游只服务流式）。判断额度必须用 standalone 的调用
方式（Bun + 流式 + 完整整形）。另外 curl 手工请求因 TLS 指纹过不了，其
429 结果无参考价值。

## 三、自愈链路（ofm-watch）

```
每分钟 timer
   │
   ├─ 读 stats.json 尾部 → 连续 ≥3 条失败？
   │     是 → 触发
   │     否 → 退出（零动作、零消耗）
   │
   ├─ 节流：距上次处置 <90s → 跳过
   │
   ├─ 换 sid：从当前代理地址取 HEAD/sid/TAIL 三段，随机新 sid
   │    对最多 6 个候选 curl ipinfo.io（8s 超时）
   │      → 取第一个能出 IP 的写入 settings.json
   │      → systemctl restart ofm-gateway（清进程内存里的断路器开窗）
   │      → 记 rotate_log（时间 | 新IP | sid | 原因）
   │    全池失败 → 记 ALL-FAILED，下周期再试
```

要点：
- **不消耗生成额度**：stats 是本地文件，探测走第三方回显（ipinfo/api.ipify），
  只有真实对话才花额度。
- **后台与看守协同**：后台设置页改代理地址 = 改同一个 `freeLane.proxyUrl`，
  看守只在连续失败时才出手，手动修改不会被覆盖。
- **服务重启 <2 秒**，客户端感知仅为一次请求失败（建议客户端开自动重试）。

## 四、运营指标怎么看

管理后台（数据看板页）：

- **请求记录**：逐请求明细（模型、token 数、耗时、首字延迟、成功率）。
- **Token 热力图 / 总量曲线**：观察消耗节奏，预判撞墙时间。
- **成功率**：连续下降 = 代理池劣化或额度将尽，提前换地址。

## 五、成本模型

| 项 | 成本 |
|---|---|
| 服务器 | 2 核 1G 可跑（standalone 空闲 <100MB） |
| 家宽代理 | 按代理套餐（按 IP 数/流量计费） |
| 上游模型 | **零成本**（免费车道），代价是额度按 IP 轮换 |
| 域名/证书 | 域名年费；证书免费（Let's Encrypt 自动续期） |

## 六、风险与边界

- **免费 ≠ 私有**：prompt 直发上游，Kilo 池明确可能记录——勿传敏感数据。
- **上游随时可变**：指纹整形规则跟随官方客户端演进，本项目用 standalone
  自动跟随（`git pull`），不需要改代码。
- **代理池质量**：住宅代理存在间歇劣化；建议主备双代理或定期评估。
- **条款风险**：使用免费额度受上游条款约束；代理使用受代理服务商条款约束。
